# 百鬼棋局开发说明

## 一、新增阵容羁绊需要添加的内容

阵容羁绊统一写在 `lineup_strategy.py`。阵容配置只描述“阵容是什么”，
通用流程和经济策略由 `script_task.py` 负责。

### 1. 添加阵容配置

策略需要包含以下内容：

- `key`：阵容稳定标识，使用羁绊拼音。
- `display_name`：OASX 中显示的中文名称。
- `shikigami_positions`：阵容式神配置。
  - 阵容文件使用“费用-编号”或中文名定位式神。
  - 数值为固定上阵位置。
  - 加载后统一转换为罗马音唯一索引，并自动关联中文名、手牌图和商店图。
- `hakuzosu_protect_position`：当阵容包含梦山白藏主时，守护之印
  装备的位置；不填写时默认装备到 1 号位。

可参考 `lineup_strategy.py` 中七角山的结构：

```python
NEW_LINEUP_CONFIG = {
    'key': 'new_lineup',
    'display_name': '新羁绊',
    'shikigami_positions': {
        '1-1': 1,
        '式神中文名': 2,
    },
}

NEW_LINEUP = build_lineup_strategy(NEW_LINEUP_CONFIG)
```

### 2. 添加式神图片资源

所有阵容共用 `shikigami` 文件夹，图片不按阵容重复存放。图片文件名由式神目录中的罗马音唯一生成：

- `shikigami/card/card_<romaji>.png`：手牌式神头像或手牌识别模板。
- `shikigami/store/store_<romaji>.png`：商店式神头像模板。
- `c/c_hakuzosu_protect.png`：梦山白藏主伴生卡守护之印。

同一式神可以被多套阵容共同引用。阵容只需填写费用编号或中文名，不再单独登记图片名；没有被当前阵容登记的式神不会参与该阵容的购买和上阵。

### 3. 注册阵容

在 `lineup.py` 中：

1. 导入新阵容策略对象。
2. 在 `LINEUP_REGISTRY` 中登记拼音键、中文显示名和策略对象。

```python
LINEUP_REGISTRY = {
    'new_lineup': {
        'display_name': '新羁绊',
        'strategy': NEW_LINEUP,
    },
}
```

`LineupBond` 会根据注册表生成。重新加载配置模型后，OASX 的“选择阵容羁绊”下拉框会自动显示新阵容的中文名称，脚本运行时会将中文选项解析为稳定的拼音键。

### 4. 新阵容应自行定义的内容

以下内容属于阵容配置：

- 阵容包含哪些式神。
- 式神固定站位。
- 梦山白藏主伴生卡守护之印的目标位置。

刷新、购买、拖动、上下阵、星级识别、手牌清理、经济下限和回目状态机属于通用功能，不应在新阵容配置中重复实现。若新阵容确实需要不同的运营动作，应先扩展通用策略接口，再由阵容配置选择对应行为。

## 二、主函数负责的内容

`script_task.py` 是百鬼棋局的通用执行器，不保存任何具体阵容的式神名单；经济策略也在这里作为当前通用运营策略维护。

### 1. 任务入口

`run()` 负责：

- 读取 OASX 中选择的阵容羁绊。
- 将中文选项解析为注册表中的拼音键。
- 加载对应阵容策略和图片规则。
- 读取执行次数与刷满鼬乐币选项。
- 读取“是否提前退出”和“剩余人数”；勾选且剩余人数大于 0 时，通过 `health_1-8` 中仍有数字的最大编号判断存活人数，连续两帧达到阈值时主动退出当前对局；填写 0 时不按人数退出。
- 导航到百鬼棋局大厅。
- 循环执行单局任务，直到满足结束条件。

### 2. 单局流程

`run_one_game()` 负责开始一局并进入回目循环。每局开始时会重置：

- 已确认的场上阵容。
- 脚本亲自上阵的位置。
- 御魂已满位置。
- 延期阵容整理任务。
- 延期经济任务及其子步骤。
- 脚本记录的商店开关状态。

结算时，主函数负责点击返回大厅、处理分享页面、安全点击以及排名页面返回，确认真正回到棋局大厅后才允许开始下一局。

### 3. 单回目状态机

`run_one_round()` 通过回目数和 `chess_mode` 协调以下阶段：

- `备`：优先选择 Buff，然后关闭商店、上式神、上御魂。
- `战`：先清理非阵容卡和纹章，再续跑未完成的经济任务。
- `鬼`：关闭商店并等待百鬼夜行自动结束。
- `待`：不执行操作，只等待状态变化。

第一套回合布局还会在“备”阶段空闲时读取 `now_time`。当剩余时间不超过 10 秒、当前没有延期阵容或经济任务且场上人数小于当前阶数时，每回目最多补做一次式神上阵；前三回合使用第二套布局时不读取该 OCR。

回目数字变化是强制边界。战后第二次“备”允许不存在；缺少该阶段时，主函数会保存阵容整理和经济任务，在后续合适阶段继续执行，不会将新回目的第一次“备”误判为旧回目阶段。

### 4. 通用上阵与下阵

主函数根据当前阵容策略提供的站位完成：

- 关闭商店后读取当前场上人数。
- 使用当前阶数作为最大上阵人数。
- 识别手牌式神并拖到策略指定位置。
- 比较手牌与场上星级，只用更高星卡替换。
- 记录脚本亲自上阵的位置。
- 回收系统可能自动放置在 9、10、11、12 号位的式神。
- 回收后立即重新上阵和装配御魂，避免系统自动上卡破坏阵型。

### 5. 通用商店与经济操作

主函数只加载当前阵容声明的商店头像，并负责：

- 扫描五个商店位置。
- 判断金币是否足够购买对应卡牌。
- 点击所有命中的阵容式神。
- 以目标头像从原商店格消失确认购买成功。
- 用当前阶数的原子操作计数器决定下一步是升级还是刷新。
- 每次只执行一个经济原子动作；刷新后立刻购买阵容式神。
- 保存计数器与待购买状态，以便跨回目续跑；检测到阶数变化时计数器归零。
- 战斗中刷新图标被技能遮挡时，使用固定位置点击并通过金币变化确认结果。

最终不保留金币的阶数由当前阵容人数决定，例如七角山有 9 名式神，因此 9 阶不保留；如果某个阵容只有 8 名式神，则 8 阶就进入不保留金币的持续刷新购买。其余阶数当前规则为：1-5 阶在 35 金币前只购买不刷新，超过后按阶数执行升级和刷新；6-7 阶保留 25 金币；8 阶保留 15 金币。

### 6. 通用手牌清理

非阵容卡清理和紧急腾位是两个不同流程：

- 非阵容卡、纹章可以直接出售，不受一星限制。
- 御魂、发现御魂和守护之印会被保护或优先处理。
- 手牌已满且非阵容卡已清空时，才启用紧急阵容卡出售。
- 紧急出售严格只允许一星阵容卡。
- 游戏会把不同种类的卡按价格排列，越靠右越便宜，因此从最右侧开始选择出售目标。
- 场上二星与手牌二星会共同参与冲三星保护；二星总数达到保护条件时，不出售该式神的一星卡。
- 场上已经三星时，取消该式神的冲三星保护。

### 7. 通用御魂和守护之印操作

主函数负责识别攻击型和功能型御魂，并根据当前已确认上阵位置选择目标。守护之印不再作为普通御魂阶段的全局扫描项；当上卡阶段成功上阵梦山白藏主后，主函数会立刻查找手牌中的守护之印，并复用通用御魂拖放接口装备到阵容配置声明的位置。
